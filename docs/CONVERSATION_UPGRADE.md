# 自然對話版本

使用者在 2026-11-26 明確要求像 ChatGPT 一樣透過對話整理分數。這次變更經使用者授權，取代舊版單題輸入、固定問卷主流程。既有研究基線與結果保留。

## 中英文介面

側欄 Language 選擇「繁體中文」或「English」。切換後按鈕、提示、核對選項和結果使用所選語言，AI 後續回覆及新摘要也按此語言生成。舊訊息、已有摘要及來源引句保留原文；切換不清空對話、不更改分數。報告圖片採全英文實際示範。

## 新的使用方式

執行 `python scripts/serve_connected.py --base-url https://car.cheng-x.online/v1`，按提示輸入密鑰，再打開 http://127.0.0.1:8501 。也可以 `python -m streamlit run app.py` 後，在側欄連線設定填入 API key。頁面不把 key 寫入檔案。若 8501 已有服務，不要重複開啟；直接刷新現有頁面。

按「開始虛構對話」，像聊天一樣描述虛構人物。可一次提到多個症狀，使用短句接續上一個問題，也可說「剛才講錯了」。AI 結合歷史對話提出候選，每次只追問一個缺口。八項清楚後，按「核對整理內容」，修改有誤的頻率，再勾選確認並計分。

範例：「最近趕功課好攰，過去兩星期有十晚都瞓唔好，第二日冇精神。但我其實仲有興趣同朋友打波。」AI 應理解睡眠頻率，同時釐清疲倦和興趣的頻率；不應要求把整句改寫成固定問卷答案。

## 架構

聊天畫面 → 獨立 mock Guard → Terra 帶歷史上下文的結構化回應 → 來源引句與欄位驗證 → 八項暫存摘要 → 使用者核對及確認 → 原有純計分函式。

`conversation.py` 管理聊天、候選及確認；`app.py` 為新入口；`questionnaire_app.py` 保留原來的問卷基線，可獨立啟動。`terra_client.py` 沿用 Responses API，增加對話輸出預算。情緒仍不參與分數。

與舊版的差異：現在允許跨題抽取，並在本次 Streamlit session 記憶體保留聊天及引句，以支援上下文；每次遠端請求傳送這些虛構內容。清除或中斷會移除該會話的聊天與候選。模型故障不更新候選、不產生結果，重試不重複加入使用者訊息。40 回合上限避免無限上下文。最後確認仍是必要的測量邊界。

## 研究與證據邊界

這是新加入的 LLM 對話理解模式。原報告的 TweetEval、64-case 規則診斷與48-case情緒pilot仍是舊實驗，不能當成新版的抽取準確率。來源引句檢查能阻止捏造不存在的引文，但不能證明模型對該句的語義理解正確。最終核對可讓使用者更正，不代表臨床驗證。

SafetyGuard 仍為示範 marker mock，並未新增真實危機判斷。只使用虛構情境。模型可能誤解、追問多餘問題或回覆延遲；尚無獨立標註的多輪對話評估。新版驗證存於 `docs/evidence/conversation` 及 `docs/evidence/bilingual`；新版整合報告已分開描述各種證據，不把舊模型指標當成新對話的準確率。
